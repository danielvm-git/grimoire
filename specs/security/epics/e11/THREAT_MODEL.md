# E11 Security Threat Model — End-to-End Browser Testing

**Epic:** e11 (E2E Browser Testing with Playwright)  
**Scope:** Adding pytest-playwright + Chromium for DOM/JS/HTMX coverage  
**Risk Level:** Low (hermetic test environment, no new production inputs)

## Threat Analysis

### 1. Chromium Sandbox & Untrusted Code
**Threat:** Malicious JS in mocked HTTP responses could escape sandbox.  
**Mitigation:** 
- Tests use seeded fixtures + httpx mocking (no live JS from external sources).
- Chromium runs in standard sandbox mode (pytest-playwright default).
- Acceptance: *LOW* — confined to test worktree, no production impact.

### 2. Test Secrets & Credentials
**Threat:** API keys, tokens in test fixtures leaked in CI logs or screenshots.  
**Mitigation:**
- Factories use placeholder/dummy credentials (`test_user`, `test_token`).
- No real GitHub tokens in test database fixtures.
- Screenshots/traces excluded from CI artifacts by default.
- Acceptance: *LOW* — no real secrets in fixture data.

### 3. Playwright/Browser Dependency Supply Chain
**Threat:** Compromised npm/PyPI package for pytest-playwright or Chromium binary.  
**Mitigation:**
- Dependencies pinned in `pyproject.toml` (uv lock enforces exact versions).
- Chromium installed via `playwright install --with-deps` (official PSF binary).
- No custom script execution in test setup.
- Acceptance: *STANDARD* — same risk as any third-party dep; no e11-specific elevation.

### 4. CI/CD Pipeline Exposure
**Threat:** Test artifacts (videos, traces) or logs expose app state to public CI.  
**Mitigation:**
- CI runs on private repo (private GitHub, self-hosted actions not applicable).
- Playwright artifacts (trace.zip, video.webm) stored locally only, not uploaded.
- Post-deploy smoke tests (e11s02) read-only (no write/admin actions in tests).
- Acceptance: *LOW* — read-only, no state mutation in live tests.

### 5. Fixture Data Persistence
**Threat:** Test database fixtures pollute production schema if loaded there.  
**Mitigation:**
- `tests/e2e/conftest.py` creates isolated database (tmp file, pytest fixture scope).
- Factories use SQLModel + aiosqlite, same schema as app (safe) but separate DB instance.
- No fixture data ever touches production database.
- Acceptance: *LOW* — fixture scope is test-only.

## Risk Summary

| Threat | CVSS | Mitigation | Verdict |
|--------|------|-----------|---------|
| Chromium sandbox escape | 3.1 | Seeded/mocked JS only | Acceptable |
| Test secrets leak | 2.5 | Dummy credentials in fixtures | Acceptable |

| CI artifact exposure | 1.0 | Private repo, no upload | Acceptable |

**Overall Epic Risk: LOW** ✓

## Approval

This epic adds test infrastructure only (no production code changes except deploy.yml smoke job). All threats are mitigated below acceptable risk. Recommend proceed without gates.
